Subnav

Section links beside the content.

Usage

A subnav is a second menu beside the page content, for a page with several sections such as settings. Put the nav.subnav first and the content right after it: the content gets the padding. Mark the open section with aria-current="page". Each link goes to its own page as usual. Below 48rem the subnav sits above the content.

The example puts it beside a main sidebar that stays collapsed to icons (data-collapsed="true").

Switching without loading a page

When all the sections are on one page (a prototype, or an app that does not reload), the links can swap the menus and the content for you. Set it up in three steps:

  1. Write one nav.subnav for each sidebar icon, with an id. Add hidden to all but the first.
  2. On each sidebar link, set aria-controls to the id of its subnav.
  3. To change the content too, put one block of content for each subnav link (hidden except the first) and set the link's aria-controls to the block's id.

A click shows the matching menu or block, hides the others and moves aria-current. The link does not go to its href. Try the icons in the sidebar.

Attributes

Attribute / element Values Description
.subnav nav Section menu, 13rem wide. Add an aria-label.
h2 child Section title, medium weight
ul > li > a child Link: .icon + label in a span (bare a without a ul also works)
aria-current page On a: the open section
aria-controls an id on the page On a sidebar link: the id of the subnav to show. On a subnav link: the id of the content block to show. The others are hidden and the link does not follow its href.
.subnav + * next element Content: fills the remaining space, with padding. From 48rem the parent lays out in a row with a divider on the right. Below that they stack with a divider underneath.
.sidebar[data-collapsed="true"] beside Main sidebar collapsed to icons. See the Sidebar page.
